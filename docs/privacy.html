Privacy & Security Policy

Project Jarvis is an open-source, localized Windows AI desktop assistant built to protect your sovereignty. We do not operate remote servers, tracking telemetry, or cloud databases.

LAST REVISED: SEPTEMBER 7, 2026 • VERSION 1.0
🛡️

Our Fundamental Privacy Guarantee

All audio streams, voice transcripts, vector memories, and Google OAuth credentials remain 100% on your local machine. Project Jarvis is physically incapable of transmitting your data to our team or any unauthorized third-party because we run no external servers or analytics telemetry.

SECTION 01 / DATA SOVEREIGNTY

Local Execution vs. Traditional Cloud AI

Most consumer voice assistants route microphone recordings, search histories, and personal emails through centralized third-party servers. Jarvis fundamentally re-engineers this model by executing models strictly on your local hardware:

Subsystem Project Jarvis Standard Cloud Voice Assistants
Voice Ingestion (VAD) ✓ Local Silero CPU ✗ Transmitted to Cloud Server
Speech-to-Text (STT) ✓ Local faster-whisper (CUDA) ✗ Remote Speech Recognition API
LLM Inference ✓ Local Qwen 3.5 4B (Ollama) ✗ Hosted Server Clusters & Training Logs
Conversation Memory ✓ Local SQLite & Vector Store ✗ Cloud User Profile & Ad Tracking
OAuth Token Storage ✓ Encrypted Local Disk Only ✗ Centralized Backend Token Vault
SECTION 02 / GOOGLE OAUTH 2.0 INTEGRATION

Information Accessed via Google APIs

When you choose to connect your Google Account with Project Jarvis, the application interacts directly with official Google OAuth 2.0 endpoints. Access is strictly confined to your personal machine and is used exclusively for the following capabilities upon your explicit command:

gmail.readonly 📬

Allows Jarvis to fetch unread email counts, senders, subject lines, and snippets to generate morning executive briefings and summarize threads on verbal command.

gmail.modify / send ✍️

Enables Jarvis to draft, preview, and dispatch replies or new email messages only after explicit vocal or click confirmation from you.

SECTION 03 / COMPLIANCE VERIFICATION

Google API Limited Use Disclosure

Project Jarvis's use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements:

  • We do not transfer or disclose Google user data to third parties.
  • We do not use Google user data for serving advertisements, retargeting, or personalized marketing.
  • We do not use Google user data to train generalized machine learning or artificial intelligence models.
  • Human employees or contributors cannot read your data, as all operations execute locally on your machine without human-in-the-loop review.
SECTION 04 / DATA RETENTION & SECURITY

Credential Storage & Encryption

OAuth access tokens and refresh tokens are stored locally in:

data/credentials/token.json • data/credentials/credentials.json

These files remain restricted to your operating system user account permissions. No telemetry, logs, or diagnostic dumps containing OAuth secrets or private messages are ever generated or exported off-device.

SECTION 05 / USER RIGHTS & REVOCATION

Revoking Access & Data Deletion

You retain sovereign authority over your authentication tokens at all times:

  1. Local Disconnect: Delete data/credentials/token.json from your installation folder to instantly sever all local API authentication tokens.
  2. Remote Authorization Revoke: Revoke Jarvis's OAuth permissions globally from your Google Account at any time via the official Google Security dashboard.
